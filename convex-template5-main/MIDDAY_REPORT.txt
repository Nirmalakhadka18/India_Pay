2. PRIORITY 1: FORM 138 / FORM 24Q TDS AUDIT CLOSURE
================================================================================
A. "DRAFT PREVIEW ONLY" SAFETY ENFORCEMENT
   - All quarterly TDS statutory file downloads in 'form-138-tds-dialog.tsx' are 
     explicitly locked with a "Draft Preview Only" status badge.
   - An amber compliance warning banner advises users that the export is internal.
   - Download filenames prepend 'DRAFT_INTERNAL_' to prevent accidental portal submission.
   - Parallel download of an 'Internal Audit Reconciliation CSV' is provided to allow 
     finance teams to perform line-by-line reconciliation of gross wages, TDS deducted, 
     ITNS 281 challans, and deposit variances before any external handoff.

B. VERIFIED FILE LAYOUT (packages/backend/convex/form138Tds.ts)
   - Caret delimiter: '^'
   - Form 138 (Income-tax Act, 2025 - Section 397(3)(b) & Rule 219) for FY 2026-27 onward.
   - Form 24Q (Income-tax Act, 1961 - Section 200(3) & Rule 31A) for earlier financial years.

   Record Structure & Control Totals:
   1. FH (File Header) — 16 Fields:
      - Line number, record type 'FH', file type 'SL1' (Form 138), caret '^', character set 'ASCII'.
   2. BH (Batch Header) — 60 Fields:
      - Deductor category ('K' company, 'G' government, 'F' firm, 'I' individual).
      - Employer TAN & PAN.
      - Financial Year & Assessment Year.
      - Government deductor details: PAO Code, DDO Code, Ministry Name (or '0000000000' / blank for non-govt).
      - 2-letter State code ('KA', 'MH', 'DL', etc.).
      - Field 53 ('Count of SD Records'): Set strictly to "0" for Q1–Q3; set to exact 
        count of SD records for Q4. (Eliminates Protean T-FV-2129 error).
   3. CD (Challan Detail) — 30 Fields:
      - 7-digit BSR code, DD/MM/YYYY deposit date, 5-digit challan serial number.
      - Minor head: 200 (TDS payable by taxpayer) or 400 (regular assessment).
      - Book entry flag ('Y' for govt transfer, 'N' for physical banking deposit).
      - Field 5 ('Count of Deductee Records'): Exact count of deductees allocated to this challan.
   4. DD (Deductee Detail) — 30 Fields:
      - Mode 'O' (regular deduction).
      - 6-digit reference serial.
      - Valid 10-char PAN or 'PANNOTAVBL' with Reason 'B' (Section 206AA 20% TDS).
      - Section Code: '1002' for Form 138 (Salary TDS) / '92B' for legacy Form 24Q.
      - Field 4: 1-based index pointing to parent ITNS 281 Challan record in CD.
      - Field 25 (Reason Code): 'A' (Lower deduction under Section 197), 'B' (No PAN / Invalid PAN), 
        or 'C' (Deduction below threshold).
      - Field 26: 10-character Section 197 Certificate Number (when Reason 'A' applies).
   5. SD (Salary Detail - Q4 Annexure II) — 30 Fields (Q4 Only):
      - Comprehensive annual salary structure: Tax Regime ('115BAC' or 'OLD').
      - Section 16 Standard Deduction (₹75,000 under New Regime / ₹50,000 under Old Regime).
      - Section 16(iii) Professional Tax deduction.
      - Previous employer gross salary and TDS deducted (from taxDeclarations table).
      - Chapter VI-A deductions (80C, 80D, 80CCD, etc.).
      - Net total tax liability, rebate, and net TDS payable.

C. DYNAMIC MULTI-CHALLAN ALLOCATION
   - The engine automatically maps deductees across available ITNS 281 challans sequentially 
     by capacity.
   - Populates CD.5 with exact allocated deductee counts and DD.4 with matching parent links.

D. OFFICIAL FVU LIMITATION STATEMENT
   - The official Protean TDS File Validation Utility (FVU 1.2 / 8.8) is distributed as a 
     closed-source Java binary (.jar / .exe) and is not installed in the execution environment.
   - In strict compliance with regulatory ethics, NO certified portal e-filing acceptance 
     is claimed. The system enforces "Draft Preview Only" status until verified via external FVU.

3. PRIORITY 2: FULL PAYROLL SYSTEM AUDIT & STATUTORY RULES
================================================================================
A. EPF & EPS (Employees' Provident Fund & Pension Scheme)
   - Wage Ceiling: ₹15,000 per month.
   - Employee Share: 12% of EPF wages (capped at ₹1,800 unless voluntary contribution on 
     actual basic 'epfOnActualBasic' is selected).
   - Employer Pension Scheme (EPS): 8.33% capped at ₹1,250/month. Automatically disabled 
     for employees aged 58 and above (all 12% redirected to Employer EPF).
   - Employer EPF Share: 12% minus EPS share (minimum 3.67%).
   - EDLI: 0.5% on wages up to ₹15,000 ceiling.
   - Admin Charges: 0.5% (Account 2) with establishment-level minimum ₹500/month check.
   - Export: Fully compliant EPFO ECR text format using '#~#' delimiter, upper-case member 
     names, and 11 standard fields.

B. ESI (Employee State Insurance)
   - Gross Wage Ceiling: ₹21,000 per month.
   - If gross wages exceed ₹21,000, employee is exempt (0% deduction).
   - If gross wages <= ₹21,000: 0.75% employee deduction, 3.25% employer contribution.

C. PROFESSIONAL TAX (PT)
   - Dynamic state-specific slab rules implemented in 'professionalTax.ts':
     - Karnataka: ₹0 for gross < ₹25,000; ₹200 for gross >= ₹25,000.
     - Maharashtra, West Bengal, Telangana, Andhra Pradesh, Tamil Nadu, and Gujarat supported.

D. LABOUR WELFARE FUND (LWF)
   - State-specific periodicity rules implemented in 'lwf.ts':
     - Karnataka: ₹20 EE / ₹40 ER annually in December.
     - Maharashtra: ₹12 EE / ₹36 ER semi-annually in June and December.
     - Other states default to applicable statutory cycles.

E. TDS (Tax Deducted at Source)
   - Default: Section 115BAC (New Tax Regime).
   - Form 12BB tax declarations supported in 'declarations.ts' for HRA (Section 10(13A)), 
     80C, 80D, home loan interest (Section 24(b)), and previous employer income.
   - Operational monthly overrides supported with reason codes ('A', 'B', 'C').

F. MAKER-CHECKER SEGREGATION OF DUTIES
   - Creator/Admin role submits payroll for approval ('submitForApproval').
   - Submitter cannot approve their own run (enforced at API level).
   - Only Workspace Owner role can approve ('approveRun') and finalize ('finalizeRun').

G. HISTORICAL PAYROLL IMMUTABILITY & SUPPLEMENTARY RUNS
   - Once a payroll run is finalized ('processed'):
     - Salary hikes, structure updates, and employee additions only impact future periods.
     - Finalized run totals, individual payroll items, and payslips remain 100% immutable.
   - Retroactive adjustments, arrears, or missed payments are handled via dedicated 
     Supplementary Payroll Runs ('createSupplementaryRun'), preserving historical baselines.
