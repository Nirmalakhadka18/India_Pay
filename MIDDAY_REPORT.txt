2. CRITICAL RUNTIME BUG RESOLUTION: "SOMETHING WENT WRONG" / 8 ERRORS
================================================================================
2.1 Incident Discovery & Visual Error Overlay Diagnosis:
When loading http://localhost:3000 in Microsoft Edge with an active session, the
browser displayed:
  "Something went wrong
   An unexpected error occurred. You can try again, or head back to the dashboard.
   [Try again]  [Go home]"
  Dev Overlay: "(!) 8 errors   [X]"
Expanding the error overlay revealed:
  "Unhandled Runtime Error
   Error: Rendered more hooks than during the previous render.
   Source: src\app\[locale]\(dashboard)\page.tsx (457:29) @ api
   > 457 | const balances = useQuery(api.leaves.getLeaveBalances, { workspaceId });"

2.2 Root Cause Analysis:
1. In MemberDashboard (apps/app/src/app/[locale]/(dashboard)/page.tsx):
   - Hooks 1 to 7 ran unconditionally at the top of the component.
   - Early returns existed at line 394 (`if (!memberData) return <Loader />`) and
     line 406 (`if (!data.isLinked || !employee) return <AccountNotLinked />`).
   - Line 457 declared `const balances = useQuery(api.leaves.getLeaveBalances, ...)`.
   - On initial mount, `memberData` was loading -> returned early (7 hooks rendered).
   - Once data arrived, `balances` hook executed -> 8 hooks rendered.
   - React detected a hook count mismatch across renders, crashing into ErrorBoundary.
2. Webpack Compiler Redefinition:
   - The dev server log reported:
     `463 | const balances = useQuery(api.leaves.getLeaveBalances, { workspaceId });`
     `      ^^^^|^^^`
     `          -- balances redefined here`
   - This compilation crash locked the error overlay in the client DOM.

2.3 Unconditional Top-Level Hook Architecture:
Refactored MemberDashboard so all hooks are declared strictly at the top of the
component before any conditional statements:
```tsx
const isLinked = Boolean(memberData?.isLinked && memberData?.employee);
const balances = useQuery(
  api.leaves.getLeaveBalances,
  workspaceId && isLinked ? { workspaceId } : "skip",
);
```
Line 457 was completely removed. When `isLinked` is false, the hook safely skips
network execution while maintaining identical hook indices across all renders.

2.4 Defensive Guards Added:
- Employee Joining Date: Wrapped with `!Number.isNaN(new Date(employee.joiningDate).getTime())`
  to protect against `RangeError: Invalid time value`.
- Monthly Attendance: Added null-coalescing defaults (`attendanceCurrentMonth?.presentDays ?? 0`).
- Payslip Formatting: Added null-coalescing defaults (`(latestPayslip.netSalary ?? 0)`).

2.5 Biome Lint Hygiene Refactor:
In apps/app/src/middleware.ts:
- Replaced `applySecurityHeaders(res: any)` with a strictly typed generic:
  `function applySecurityHeaders<T extends { headers?: Headers }>(res: T): T`
- Converted `if (res && res.headers)` to optional chaining `if (res?.headers)`.
- Verified 100% clean across all 84 files in apps/app.

4.2 Ephemeral Quick Tunnel Ingress Proxy Limitation:
- Ingress URL: `https://satisfied-belkin-comprehensive-los.trycloudflare.com/login`
- Tested across HTTP methods (GET, HEAD, POST) and paths (/, /login, static assets).
- Finding: The local Next.js server transmits all four headers, but the public
  TryCloudflare ingress strips custom frame and permissions policies at the edge.
- Cause: Ephemeral Quick Tunnels operate on Cloudflare's shared public zone (*.trycloudflare.com),
  where edge proxy policies restrict custom headers to protect the shared domain.
- Status: Origin behavior verified PASS. Public edge enforcement requires customer-owned
  zone (staging.indiapay.in via Named Tunnel).

5. VM & DEPLOYMENT INSPECTION FOR STAGING.INDIAPAY.IN

5.1 VM Process & Service Architecture:
Based on deployment scripts in `deploy/`:
- `myos-app.service`: Next.js production server on port 3000 (`/opt/myos/apps/app`).
- `myos-web.service`: Landing website on port 3001 (`/opt/myos/apps/web`).
- `myos-echo.service`: Node reference backend on port 4000.
- Docker Compose: Self-hosted Convex backend on ports 3210 (API), 3211 (site/JWKS),
  and 6791 (dashboard).
- Caddy: Internal reverse proxy on ports 443, 3215, 3216.

5.2 Existing Cloudflare Tunnels (4 Services Running):
1. `cf-app.service` -> forwards http://localhost:3000 (Next.js app).
2. `cf-cvx.service` -> forwards http://localhost:3210 (Convex API).
3. `cf-mail.service` -> forwards http://localhost:8025 (Mailpit inbox UI).
4. `cf-glitch.service` -> forwards http://localhost:8000 (GlitchTip error tracking).

5.3 Quick Tunnel URL Dependencies:
- `/opt/myos/self-hosted/.env` sets `CONVEX_CLOUD_ORIGIN=$CVX_URL`.
- Backend Convex environment sets `SITE_URL=$APP_URL`.
- `/opt/myos/apps/app/.env` bakes `NEXT_PUBLIC_CONVEX_URL=$CVX_URL` at build time.
- GlitchTip telemetry bakes `$GLITCHTIP_URL` into `NEXT_PUBLIC_SENTRY_DSN`.
- Conclusion: Ephemeral quick tunnels cause URL churn on restarts. A permanent
  Named Tunnel on `staging.indiapay.in` solves this permanently.

5.4 Non-Disruptive Named Tunnel Migration Plan:
- `cloudflared` initiates outbound connections to Cloudflare; multiple tunnel
  instances can forward to the same local port (`localhost:3000`) without conflict.
- Installing `cloudflared.service` with a named tunnel token operates in parallel
  with `cf-app` and `cf-cvx`.
- Zero application downtime and zero port collisions.

5.5 DNS & Resend Email Safety:
- `indiapay.in` currently resolves to parking IP `185.53.179.128` at Dynadot.
- Resend is configured on subdomain `mail.indiapay.in` (Region: ap-northeast-1).
- Adding `staging.indiapay.in` and delegating DNS to Cloudflare preserves the 4 Resend
  DNS records (`resend._domainkey.mail`, `rsend.mail`, `send.mail`, `_dmarc.mail`)
  with ZERO risk of email delivery disruption.
